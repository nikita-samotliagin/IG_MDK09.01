**Студент:** Самотлягин, группа 4ИСП9-45

**Система:** портал «Конференции.РФ» — бронирование помещений для проведения Всероссийских конференций

## 1. Описание предметной области

Организация проводит Всероссийские конференции и сдаёт свои помещения под их проведение: аудиторию, коворкинг и кинозал. Раньше заявки принимали по телефону и электронной почте. Из-за этого заявки терялись, одно помещение бронировали дважды, а организатор не знал, рассмотрена ли его заявка.

Портал переводит приём заявок в онлайн:

- организатор конференции регистрируется, выбирает помещение, дату и время начала, способ оплаты и отправляет заявку;
- администратор видит все заявки в одном месте и меняет их статус;
- после завершения мероприятия организатор оставляет отзыв о помещении и обслуживании.

**Основные понятия предметной области**

| Понятие | Что означает |
|---|---|
| Помещение | зал, который сдаётся под конференцию: название, место (корпус, этаж), вместимость, описание, фото |
| Мероприятие | конференция или её секция: название, дата и время начала, помещение (место), описание |
| Заявка | просьба участника провести мероприятие в помещении; имеет способ оплаты и статус |
| Статус заявки | «Новая» → «Мероприятие назначено» → «Завершено» |
| Способ оплаты | «При очном посещении» или «Перевод по СБП» |
| Отзыв | оценка от 1 до 5 и текст; оставляется один раз по завершённой заявке |

## 2. Назначение системы и пользователи

**Назначение:** приём, учёт и обработка заявок на проведение конференций в помещениях организации, сбор отзывов.

| Пользователь | Кто это | Зачем пользуется порталом |
|---|---|---|
| Гость | любой посетитель сайта | узнать, какие есть помещения, и зарегистрироваться |
| Участник | организатор конференции (сотрудник вуза, компании, НКО) | подать заявку, следить за её статусом, оставить отзыв |
| Администратор | сотрудник организации | рассматривать заявки, назначать и завершать мероприятия |

## 3. Роли и функциональные требования

### 3.1. Гость

| Код | Требование |
|---|---|
| Г-1 | Просмотр главной страницы со списком помещений: фото, название, место, вместимость, описание |
| Г-2 | Регистрация. Поля обязательны: логин (латиница и цифры, не менее 6 символов, уникальный), пароль (не менее 8 символов), ФИО (кириллица и пробелы), телефон в формате 8(XXX)XXX-XX-XX, e-mail |
| Г-3 | Ошибки заполнения показываются под каждым полем; введённые данные (кроме пароля) не стираются |
| Г-4 | Переход со страницы регистрации на авторизацию и обратно («Еще не зарегистрированы? Регистрация») |

### 3.2. Участник

| Код | Требование |
|---|---|
| У-1 | Авторизация по логину и паролю; при неверных данных — сообщение «Неверный логин или пароль» |
| У-2 | Создание заявки: помещение, название мероприятия, дата и время начала (только в будущем), способ оплаты, описание (необязательно). Новая заявка получает статус «Новая» |
| У-3 | Просмотр **только своих** заявок: номер, мероприятие, помещение, дата начала, оплата, статус, дата подачи |
| У-4 | Отмена своей заявки, пока она в статусе «Новая» |
| У-5 | Отзыв (оценка 1–5 и текст) — только после того, как заявка получила статус «Завершено»; по одной заявке — один отзыв |
| У-6 | Личный кабинет: данные профиля, количество заявок по статусам, ближайшее назначенное мероприятие |
| У-7 | Выход из системы |

### 3.3. Администратор

| Код | Требование |
|---|---|
| А-1 | Вход под учётной записью **Conf2027 / Demo77** |
| А-2 | Просмотр всех заявок всех участников с контактами участника (ФИО, логин, телефон, e-mail) |
| А-3 | Смена статуса заявки: «Новая» → «Мероприятие назначено» → «Завершено». Вернуть статус назад нельзя |
| А-4 | Фильтрация: по статусу, по помещению, по периоду дат начала, поиск по логину, ФИО или названию мероприятия |
| А-5 | Счётчики заявок по статусам |
| А-6 | Просмотр отзывов в карточке заявки |

## 4. Нефункциональные требования

### 4.1. Адаптивность

- Корректное отображение на смартфоне 390×844, планшете (от 768 px) и ПК (от 992 px), без горизонтальной прокрутки.
- На смартфоне меню открывается кнопкой, таблицы превращаются в карточки.
- Элементы управления высотой не меньше 44 px, чтобы попадать пальцем.
- Корректное отображение в Chromium и Firefox на ПК и при ширине экрана 390 px.

### 4.2. Безопасность

- Пароли хранятся только в виде хеша (`password_hash`, bcrypt).
- Все запросы к БД — подготовленные, с параметрами (защита от SQL-инъекций).
- Весь пользовательский вывод экранируется (защита от XSS), заголовок Content-Security-Policy.
- CSRF-токен в каждой форме, отправляющей данные.
- Разграничение доступа: участник не видит чужие заявки и панель администратора; гость перенаправляется на вход.
- После 5 неверных попыток входа логин блокируется на 5 минут.
- Cookie сессии с флагами HttpOnly и SameSite, новый идентификатор сессии после входа.

### 4.3. Производительность

- Главная страница загружается быстрее 2 секунд на мобильном интернете (4G).
- Изображения в формате WebP (с JPEG для старых браузеров), подгрузка картинок ниже первого экрана — `loading="lazy"`.
- Индексы в БД по полям, по которым идёт фильтрация (статус, пользователь, дата начала).
- Один файл стилей и один файл скриптов, без тяжёлых библиотек.

### 4.4. Прочие требования

- Интерфейс на русском языке, оформление по «Руководству по стилю» заказчика: цвета #007bff, #0d47a1, #6c757d, #f8f9fa, #ffffff; шрифт PT Sans.
- Стек: PHP 8, СУБД SQLite (для разработки) или MySQL 8 (для сервера), HTML5, CSS3, JavaScript.
